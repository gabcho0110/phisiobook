# PhysioBook

Дигитален асистент за физиотерапевти, рехабилитатори и кинезитерапевти.
Управление на пациенти, график, процедури, сесии, документация и ценоразпис.

**Автори:** Алекс Тодоров, Габриел Атанасов
**Сайт:** https://physiobook.eu

---

## Какво представлява

PhysioBook е Progressive Web App (PWA), която се инсталира на телефон или таблет
и работи като мобилно приложение. Интерфейсът е изцяло на български език.

### Модули

| Модул | Описание |
|---|---|
| **Табло** | Обобщена статистика |
| **Пациенти** | Регистър и медицински профил на пациентите |
| **Досиета** | Документация по пациент |
| **График** | Седмичен и дневен изглед, drag & drop |
| **Замествания** | Отсъствия и покритие на смени |
| **Процедури** | Каталог и шаблони за процедури |
| **Тестове и скали** | Оценъчни тестове |
| **Инвентар** | Наличности и движения |
| **Ваучери** | Статуси и проследяване |
| **Упражнения** | Библиотека с упражнения и програми |
| **Документация** | Медицински документи |
| **Ценоразпис** | Цени по дата |
| **Настройки** | Клиника, модули, потребители |
| **Моят портал** | Изглед за пациента |

Приложението поддържа **няколко клиники** (clinic switcher) и включване/изключване
на модули по отделно за всяка клиника.

## Технологичен стек

- **Vanilla HTML / CSS / JavaScript** — без framework и без build стъпка
- **Firebase Realtime Database** — modular SDK v10.12.2 (ESM от CDN)
- **Font Awesome 6** (CDN)
- **PWA** — `manifest.json` + икони 192/512

> Няма `package.json`, няма зависимости за инсталиране. Приложението се състои от
> статични файлове и работи директно в браузър.

## Как да стартирате локално

Приложението няма build стъпка. Достатъчно е да го сервирате като статични файлове
(не отваряйте `index.html` директно през `file://` — Firebase и ES модулите
изискват HTTP).

```bash
# Python
python3 -m http.server 8080

# или Node
npx serve .
```

След това отворете http://localhost:8080

## Вход в системата

Входът става с **6-цифрен код**, който е постоянен за всеки потребител или пациент.
Кодовете се управляват от административния панел (`admin.html`) и **не трябва да се
променят** — те са идентификаторът на потребителя.

## Service worker

`sw.js` е коректна, но **умишлено изключена** имплементация. В края на `index.html`
има блок, който дерегистрира всички service workers при зареждане. Причината:
приложение, което често се обновява, не трябва да сервира залежала стара версия
от кеша.

Ако все пак искате офлайн кеширане, премахнете блока
`<script> ... serviceWorker ... </script>` в края на `index.html`. `sw.js` вече е
написан правилно (network-first за HTML, stale-while-revalidate за статични ресурси).
